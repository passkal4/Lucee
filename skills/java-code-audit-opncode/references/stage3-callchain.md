# 阶段3：调用链追踪策略

## 目标
从高危 Source 到 Sink 建立可验证的数据流路径，并输出关键约束条件。

## 追踪方法

### A. 静态分析主路径
1. 从 `priority_queue` 中取 P0 条目。
2. 定位入口方法（Controller/Action/Message Handler）。
3. 构建方法级调用图（service -> dao -> util）。
4. 追踪污点传播：参数、返回值、字段、集合元素。
5. 到达 Sink 时记录：
   - 触发参数
   - 条件分支
   - 前置校验/过滤

### B. 符号执行/约束补充（可选）
- 对复杂条件分支使用符号约束判断“是否可达”。
- 输出最小触发条件集合（而非攻击脚本）。

## 分批追踪（大项目）
- Batch 1: 未鉴权 + 高危 Sink
- Batch 2: 已鉴权但低权限可达
- Batch 3: 中低危链路

每批次产物：
- `chains_batch_<n>.md`
- `unresolved_batch_<n>.md`（无法解析的动态分发/反射点）

## 误差控制
- 反射、动态代理、SPI、AOP 切面要补充边。
- 对外部库方法标记“黑盒节点”。
- 对无法证明可达链路降置信度，不直接定漏洞。
